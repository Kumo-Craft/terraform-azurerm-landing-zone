# DiskEncryptionSet

Creates an Azure Disk Encryption Set (DES) — the object that binds managed disks to a
customer-managed key in Key Vault, turning `EncryptionAtRestWithPlatformKey` into
`EncryptionAtRestWithCustomerKey`.

That is the state the ALZ guardrail `deny-osanddatadisk-cmk` (initiative
`Enforce-Guardrails-Encrypt-CMK`) requires, alongside the built-in
*OS and data disks should be encrypted with a customer-managed key*
(`702dd420-7fcc-42c5-afe8-4026edd20fe0`).

The Key Vault and the key are **inputs** — compose [`../KeyVaultStack`](../KeyVaultStack)
and [`../KeyVault-Key`](../KeyVault-Key). This module never creates either: a DES is
disposable, a key is not, and losing the key makes every disk bound to it unreadable.

## Prerequisites

| Requirement | Why |
|---|---|
| Key Vault **purge protection enabled** | Azure refuses a DES pointing at a purgeable vault. **Irreversible** on the vault. |
| Key Vault soft delete | Implicit on any vault created since 2021. |
| RSA 2048+ key (RSA-HSM needs a Premium vault) | `wrapKey` / `unwrapKey` are the operations the DES uses. |
| DES region == disk region | A DES is regional; a disk cannot reference one from another region. |

## Usage

### Standalone

```hcl
module "des" {
  source = "../DiskEncryptionSet"

  subscription_acronym = "avd"
  environment          = "prod"
  region_code          = "gwc"
  workload             = "01"          # → des-avd-prod-gwc-01

  resource_group_name = "rg-avd-prod-gwc-sh-dev"
  location            = "germanywestcentral"

  # Versionless id — required because auto_key_rotation_enabled defaults to true.
  key_vault_key_id = module.cmk.versionless_ids["disks"]
  key_vault_id     = module.kv.key_vault_id

  tags = local.tags
}
```

### Attaching a disk

```hcl
resource "azurerm_windows_virtual_machine" "this" {
  # ...
  os_disk {
    disk_encryption_set_id = module.des.id
    # ...
  }

  # ⚠️ NOT optional. The DES identity only gets key access AFTER the DES
  # exists, so `module.des.id` alone can resolve before the grant lands.
  # A disk attached to a DES whose identity cannot unwrap the key fails
  # AT THE DISK, with an error that says nothing about RBAC.
  depends_on = [module.des]
}
```

> ⚠️ **Attaching a DES to an EXISTING VM requires the VM to be deallocated.**
> Not rebuilt — deallocated. Terraform plans this as an in-place update
> (`~ os_disk { + disk_encryption_set_id }`, no replacement); Azure is what
> refuses the change on a running VM:
> *"Your existing disks must not be attached to a running VM in order for you
> to encrypt them"* —
> [docs](https://learn.microsoft.com/azure/virtual-machines/disks-enable-customer-managed-keys-portal#enable-on-an-existing-disk).
>
> Procedure: stop → apply → start. The disk is kept; only the key that encrypts
> it changes.
>
> Later **key rotation** is transparent: *"Virtual Machines aren't rebooted
> during automatic key rotation."*

## Two traps this module guards against

**1. Rotation that silently never happens.** `auto_key_rotation_enabled = true` requires a
**versionless** key id (`.../keys/<name>`). Pass a versioned one and the DES pins to that
version forever — nothing errors, the key just never rotates. The module refuses the
combination at plan time.

**2. `ConfidentialVmEncryptedWithCustomerKey` on a Trusted Launch host.** That mode is for
**Confidential VMs only**. Selecting it for a Trusted Launch VM makes the VM unbootable.
The module accepts the value (it cannot know what will consume the DES) but the caller owns
the check. For Trusted Launch, `EncryptionAtRestWithCustomerKey` is the correct choice.

## RBAC

The module grants the DES identity **Key Vault Crypto Service Encryption User** on
`key_vault_id` — wrap/unwrap/get on keys, nothing else.

Do **not** substitute *Key Vault Crypto Officer*: it can delete keys, and the identity that
encrypts your disks has no business being able to destroy the key that decrypts them.

Set `key_vault_id = null` to opt out when a platform pipeline owns all vault RBAC. That is
a deliberate choice, not a default — without the grant, disks fail to attach.

## Inputs

| Name | Type | Default | Description |
|---|---|---|---|
| `name` | `string` | `null` | Explicit name. When null, generated by `../Naming` as `des-{acr}-{env}-{region}-{workload}`. |
| `subscription_acronym` / `environment` / `region_code` / `workload` | `string` | `null` | Naming segments. All four required when `name` is null. |
| `resource_group_name` | `string` | — | Resource group holding the DES. |
| `location` | `string` | — | Must match the disks' region. |
| `key_vault_key_id` | `string` | — | Versionless when rotation is on, versioned when off. |
| `key_vault_id` | `string` | `null` | Vault to grant on. `null` opts out of the grant. |
| `auto_key_rotation_enabled` | `bool` | `true` | Follow the key's rotation policy. |
| `encryption_type` | `string` | `EncryptionAtRestWithCustomerKey` | See the traps above. |
| `identity_type` | `string` | `SystemAssigned` | Or `UserAssigned`. |
| `user_assigned_identity_ids` | `list(string)` | `[]` | Required iff `identity_type = "UserAssigned"`. |
| `federated_client_id` | `string` | `null` | Cross-tenant CMK only. |
| `tags` | `map(string)` | `{}` | Tags. |

## Outputs

| Name | Description |
|---|---|
| `id` | DES resource ID — feed to `disk_encryption_set_id`. |
| `name` | DES name. |
| `principal_id` | DES managed identity principal ID. |
| `role_assignment_id` | The key grant. `null` when `key_vault_id` was not supplied. Depend on this before attaching disks. |
| `key_vault_key_url` | The key URL the DES resolved — with rotation on, this follows the current version. |
